<h1>Deploy Site from Git</h1>

<!-- wp:betterdocs/api-tryit {"method":"post","path":"/servers/{uuid}/sites/git","refId":7757} /--><!-- wp:paragraph -->
<p>Creates a site on the server and deploys it from a git repository. This is an asynchronous operation — the response returns as soon as the deployment has been accepted, and the site remains in a provisioning state until the first deploy finishes. The whole creation is atomic: if any step fails, no partial site is left behind.</p>
<!-- /wp:paragraph --><!-- wp:paragraph -->
<p><strong>Choosing a repository source</strong></p>
<!-- /wp:paragraph --><!-- wp:list -->
<ul>
<li><strong>Connected provider</strong> — send <code>repository.provider_uuid</code> + <code>repository.full_name</code>.
Use this for private repositories: xCloud authorises the deploy key on the repo for
you, and can install a push-to-deploy webhook (<code>enable_push_deploy</code>).</li>
<li><strong>Public URL</strong> — send <code>repository.url</code> (an <code>https://</code> clone URL). Cloned anonymously;
no key required. The <code>.git</code> suffix is added for you if you omit it.</li>
</ul>
<!-- /wp:list --><!-- wp:paragraph -->
<p><strong>Private SSH URLs (<code>git@…</code>) are rejected.</strong> A deploy key has to be authorised on the remote <em>before</em> the first clone, and that handshake cannot be completed inside a single API call — a key minted here would not exist on the remote, so the deploy would fail later at clone time rather than failing now. Connect a git provider instead.</p>
<!-- /wp:paragraph --><!-- wp:paragraph -->
<p><strong>Defaults worth knowing</strong></p>
<!-- /wp:paragraph --><!-- wp:list -->
<ul>
<li><code>repository.branch</code> — omit to use the repository's default branch. - <code>database</code> — only WordPress gets a database by default. Everything else defaults to
none; pass <code>database.provider: in_server</code> to request one.</li>
<li><code>php_version</code> — falls back to the server's version. - <code>site_user</code>, and the database name/user/password when not supplied, are derived for you.</li>
</ul>
<!-- /wp:list --><!-- wp:paragraph -->
<p>Requires the <code>write:servers</code> scope.</p>
